# 平板开发与远程构建原则

耗时、耗电的编译、打包与批量软件测试默认交给经用户授权的远程 Omarchy / Arch 构建机。平板承担编辑、交互预览、安装验收与真实硬件测试。远程构建机暂时不可达时，保留任务并说明原因，不自动让平板执行满负载构建。

## 工作划分

| 工作 | 默认位置 |
| --- | --- |
| Rust / C / C++ 编译、打包、静态分析、批量测试 | 远程构建机 |
| 源码编辑、轻量检查、任务状态和日志查看 | 平板或远程机，按开销选择 |
| 触屏、实体键、Fcitx 实际输入、锁屏、4G、GPS、电池与功耗验收 | 平板实机 |
| 系统更新、驱动和固件操作 | 对应设备，遵循该设备的具体授权 |

远程软件测试通过不等于平板实际验收通过。

## 工作目录与任务恢复

- 每台构建机使用独立的项目根目录，内部划分源码、任务、产物与缓存；不占用其他项目目录。
- 通过专用 SSH 密钥连接。账号、地址、凭据引用与主机指纹留在私人运维档案。
- 长任务放在独立 tmux 服务实例中，避免与已有会话重名。SSH 断开不终止任务；主机重启后的恢复另行设计。
- 同步源码使用显式文件清单或源码快照；不将整个主目录、钥匙串、代理节点、录音、运行数据库上传。
- 删除、覆盖或清理只允许作用于当前项目确认归属的任务目录；不对用户主目录执行同步删除。
- 并发数按构建机负载设置，初期从 2 个编译任务开始；不默认独占全部 CPU。

## 构建与交付

目标是建立与平板依赖兼容的 Arch 干净构建环境，固定源码版本、工具链及依赖版本，按提交生成产物、日志和校验值。两个设备都使用 Arch 并不能保证 Qt、Fcitx、glibc 等 ABI 一致；构建前仍需核对。

面向平板的产物不得使用构建机的 `-march=native` 优化。产物下载后校验完整性，在平板安装前保留旧版本及恢复入口。构建完成与安装启用分成两个明确步骤。

工具与软件包遵循 Omarchy → Arch 官方 → 厂商上游 → 社区的现有优先级。编译依赖优先隔离在专用构建环境，不为方便而升级构建机其他项目的依赖。

## 当前验证范围

2026年10月17日已验证一台授权构建机的 Cloudflare 隧道 SSH 登录、独立 Ed25519 公钥登录、专用目录、独立 tmux 会话、SSH 断开后继续编译并执行小型 C 程序，以及下载产物的 SHA-256 一致性。

完整输入法构建、Rust 工具链、干净构建环境、自动派发队列、重启恢复和版本化安装尚未完成。本页确定工作原则，不代表这些能力已部署。
