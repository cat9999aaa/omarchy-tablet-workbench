# 输入法 0.2.6 短暂失焦修复验证

2026-10-18，Omarchy / Hyprland 0.56.2。UI与后端0.2.6已在首台平板切换，ready=true，单后端。保留UI0.2.5和后端0.2.4恢复入口。

## 问题与行为

Paseo保持同一前台窗口时，Fcitx曾短暂失焦约两秒；旧后端立刻隐藏键盘，焦点恢复不会自动重开。此次不判定Paseo失焦的内部原因，只修复已批准的显示行为。

同窗口短暂失焦保留手动打开的键盘，禁止提交文字；有效焦点恢复后继续输入。窗口切换、Hyprland空activewindowv2事件、主动收起关闭面板。窗口切换后等待新的输入服务状态确认，旧在途查询不能重新授权。原有草稿取消语义保留。

## 结果

- 旧生产0.2.4后端运行新增测试，按预期在“同窗口失焦保留面板”断言失败。
- 最终远程隔离构建与9项CTest全部通过；平板4项隔离ABI检查通过。
- 真实QML→后端→Fcitx→临时GTK输入框：提交测试文字通过；同窗口失焦2.2秒面板保留，失焦提交被拒绝；恢复后继续提交通过；手动收起后焦点恢复仍隐藏。未向用户应用注入文字。
- 真实QML在锁屏时取得无活动窗口、解锁时取得有效窗口；新增Hyprland事件连接实际加载通过。
- 独立评审发现的锁屏事件依赖和旧焦点重用问题均修正，复核无剩余Critical/Important。
- 原Fcitx服务与整个桌面未重启，仅按官方插件生命周期切换输入面板。

中间失败分别包括测试释放错误的旧D-Bus连接，以及临时GTK输入框恢复焦点默认全选导致追加断言不成立；前者改为释放实际owner，后者使用不全选的聚焦。修正后重跑通过，未通过放宽产品断言掩盖失败。

## 仍待验收

用户Paseo手指输入、先失焦再锁屏与解锁后保持关闭、横竖屏、冷启动与长期使用未由上述软件测试推定。没有建立compositor window ID与Fcitx context的强映射。

## 锁屏事件依据

核对当前Hyprland提交：锁屏调用[rawSurfaceFocus(nullptr)](https://github.com/hyprwm/Hyprland/blob/efb50993780079460b0cbed1363e2166a2de1d9f/src/managers/SessionLockManager.cpp#L89)，清除seat焦点时发送[空activewindowv2](https://github.com/hyprwm/Hyprland/blob/efb50993780079460b0cbed1363e2166a2de1d9f/src/desktop/state/FocusState.cpp#L216)。这条事件不依赖应用内部输入框再次失焦。其他compositor未验。
