# 地图定位适配与网络入口验收 · 2026-10-17

已部署应用专用GPS适配器0.1.0、用户“平板地图”入口，网络面板1.3.8加入“打开地图”。GPS服务仍按需控制；没有修改系统Qt插件或系统地图入口。真实卫星定位、地图居中和手指操作未验，不能以本次模拟数据替代。

## 软件与本机证据

- Qt公开定位工厂接口连接现有本机gpsd。固定localhost端口，不接管串口、不新建守护进程、不记录轨迹。
- 授权远程Arch隔离构建：13个Qt行为场景（Qt报告15项包含初始化/清理）与默认源工厂两个CTest通过；4项启动器检查通过。首次红测与四项审查回归失败保留，修复后通过。
- 默认源独立进程连续30次选择正确。私有插件优先级2000，高于当前Qt的GeoClue2；二进制工厂探针也检查实际元数据，避免增量构建留下旧元数据。发布使用干净构建目录。
- 回传摘要、源文件摘要及本机QtCore/Positioning6.11.2匹配。平板私有网络命名空间内，工厂与四项针对性兼容场景通过。
- 实际Marble Maps进程在私有网络命名空间运行，已加载适配插件、发送WATCH订阅并接收19条人工定位报告，运行结束正常清理。服务端和应用的localhost与宿主隔离，未触及真实GPS。地图画面可见；尚未验证人工位置居中或真实卫星位置。
- 网络入口3项隔离测试通过：先检查版本和完整性，再启动；检查失败不启动；严格飞行模式不从该入口激活定位。
- GPS页实际外框640×604，三项操作为开始/停止定位、打开地图、卫星详情，长内容使用内部滚动。
- 发布工具真实执行1.3.7→1.3.8→恢复1.3.7→再次1.3.8，每步均由运行探针确认；旧版本、事务及恢复备份保留。此次只恢复用户面板，不代表后端、系统服务或所有插件均做过真实恢复。

## 恢复与来源

普通`marble-maps`启动不加载本应用专用插件。网络面板可用版本发布工具恢复上个manifest；GPS服务和网络线路不随面板恢复改变。Qt升级后私有启动器拒绝旧ABI，应重新远程构建验收。
