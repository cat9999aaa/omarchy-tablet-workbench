已批准总架构的阶段2/4实施批次，继续inline执行；不改变设备网络与启动策略。

## 目标

共享UI、网络、控制台、电池及辅助工具使用同一个可复现验收入口。GitHub托管运行器自动运行；个人远程机仍用于Arch/ABI与完整输入法编译。失败、缺依赖和超时均不得产生通过报告。

## 约束

- 此批源码权威在仓库scripts/acceptance，引用modules的脱敏快照；不复制私人配置。
- 本机轻量编辑，远程隔离批量测试；GitHub仅托管运行器，无私人SSH/网络凭据。
- push/普通pull_request/手动触发；contents只读，Action固定提交，禁用checkout凭据保留。依赖更新只提PR，不自动合入或安装。
- 检查软件逻辑和布局，不代替实机、整机编译、断网恢复、物理手势或冷启动验收。

## 步骤

1. 单一验收器：测试失败/超时/缺工具不会误报；各子进程独立，输出新目录，JSON报告可追查。共享组件副本一致性作为门禁。
2. 接入现有Python/Node/QML测试，远程验证便携快照及报告；不引入后台进程。
3. GitHub workflow、dependabot及说明；新提交实际云端通过再声称CI可用。
4. 一次独立审查，修复重要问题，记录结果与恢复；更新验收/启明入口。

## Review Focus

缺依赖是否误跳过；测试异常是否仍跑剩余检查并返回失败；输出是否覆盖旧证据；公开CI是否能接触本机凭据/网络；脚本是否误执行真实IME或网络操作；源码副本漂移是否被发现。
