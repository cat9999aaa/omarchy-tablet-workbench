# 原生代理管理界面与交互规格

日期：2026-10-18；状态：已制作可点击设计原型，等待用户审阅。本规格不表示 Qt/QML 管理程序、Rust 服务或更新流水线已经实现。

## 目的与范围

用户主要通过触屏操作一台性能和电池受限的 Omarchy 平板，需要明确知道物理网络、代理和分流是否正常，少点几次完成开关和选节点，并避免重复进程、切页跳动以及失败后不知如何恢复。

本次交付是七页可点击原型与交互规格。原生程序仍遵循[代理总架构](2026-10-17-native-proxy-design.md)，源码依据见[上游研究](../../research/2026-10-18-v2rayn-source-review.md)。本规格细化并替代总架构中旧的页面划分：DNS 高级入口归“分流”，TUN 运行设置归“设置”。其他架构规则保留。

原型位置：[演示说明](../../mockups/proxy-control-v1/README.md)、[可打开的页面](../../mockups/proxy-control-v1/index.html)。它只含虚构节点和状态，不接管正在使用的网络。

## 统一界面

一个固定外框：导航、标题与操作栏、常驻状态栏、可滚动内容、状态页脚。横竖屏切页不改变外框尺寸。普通页禁止另外弹出终端；具体技术错误留在可展开的诊断详情中。

- 七页依次为总览、节点、订阅、分流、更新、诊断、设置。宽屏侧栏，窄屏使用页面选择控件；生产 QML 应复用工作台导航组件。
- 常驻状态栏分别显示物理出口、代理实际状态、当前分流模式和 TUN 状态。节点名称在总览与快捷面板直接显示。物理出口不显示为 TUN 虚拟网卡。
- 触屏主按钮至少 48 个逻辑像素高，文字不依赖悬停；错误使用文字和颜色共同表达。支持焦点轮廓、对话框焦点限制和 Escape 取消。
- 深色中性底色、绿色主操作、黄色待处理、红色失败。本原型是静态样式草图；正式版本映射共享主题变量，跟随 Omarchy 主题，而非把 HTML 配色硬编码进所有模块。
- 横屏采用并排信息卡；竖屏改为纵排；窄屏主操作占满可用宽度。溢出内容在内部滚动，固定状态和底部操作保持可见。
- 完整管理和三指控制台快捷入口共用一份状态源。收起管理界面不停止后台服务，明确点“关闭代理”才停止。

## 页面与操作

| 页面 | 必须展示 | 主要操作与边界 |
| --- | --- | --- |
| 总览 | 连接状态、当前节点、物理出口 → TUN → 分流 → 出口、局域网/ZeroTier策略 | 开关代理、选节点、进入诊断；不把“进程启动”直接显示为“互联网可用” |
| 节点 | 当前节点置顶、名称/组/地区、检测结果与时间 | 搜索、手动检测、选择；候选失败保留原节点；检测按需且限制并发与流量 |
| 订阅 | 来源别名、更新时间、节点数量、更新结果 | 导入/更新先预览差异；隐藏认证字段；删除当前节点必须明确处理；原型只展示虚构导入 |
| 分流 | 规则/全局/直连、当前运行模式、待应用修改、示例去向 | 先编辑后应用；高级 DNS/规则编辑器单独实现；静态推演标“预计”，实测才标“实际” |
| 更新 | 程序、核心组合、规则分别列出当前/候选版本 | 展示变更、验证、激活与恢复结果；大文件计费网络可延后；不把更新程序等同更新规则 |
| 诊断 | 物理链路、DNS、本地代理、TUN、目标访问 | 先显示最早失败环节、具体下一步；按需展开脱敏技术详情；原型未做真实检测 |
| 设置 | 登录恢复意图、计费网络下载策略、TUN、隐私 | 手动关代理后不自动重开；TUN 开关说明影响；真实权限使用系统认证 |

## 配置与状态契约

UI 的展示数据分为期望状态、读回状态、观测时间和操作状态。服务不可达或读数过期时显示“状态未知/数据已过期”，不能继续显示绿色“已连接”。原型只演示其中常用状态，完整字段与事件协议在后续实现计划中落实。

配置有三个独立版本：编辑草稿、当前生效、上一可用。分流选择不直接写运行配置；应用执行能力检查、配置语法校验、必要授权、受控切换、健康读回，然后才提交成功状态。失败显示发生在哪一环、当前用哪份配置、能做什么。

离开未应用修改需明确放弃或继续编辑；关闭界面使用相同规则。取消授权保留草稿与旧运行配置。配置操作由服务串行执行并提供操作 ID，过时异步结果不能覆盖新状态；重复点击不会启动第二套服务或第二个 TUN。原型的延迟计时只演示过程，不是性能数据。

分流三模式均保留传输基础旁路与本地/LAN默认保护；ZeroTier 外层流量不进入代理 TUN。正式版允许的高级覆盖必须显式校验，普通订阅不能覆写保护规则。“全局”指可代理业务流量使用代理，不代表所有本地控制流量也被代理。

手动关闭优先于自动恢复。飞行模式暂停恢复和在线检测；熄屏本身不改变联网意图。NetworkManager 继续拥有物理链路；本模块不另建一套 Wi-Fi/4G 控制器。

## 失败与恢复

| 事件 | 可见反馈 | 处理 |
| --- | --- | --- |
| 没有物理网络 | 等待网络，配置保留 | 引导用户恢复 Wi-Fi/4G；不重复拉起核心 |
| 节点切换失败 | 失败原因、仍在使用的旧节点 | 回到上一可用配置；不得宣称已有 TCP 会话无损 |
| 配置校验失败/权限取消 | 修改未生效 | 保留旧配置，允许修正或放弃草稿 |
| 更新失败 | 候选版本与失败环节、恢复结果 | 尝试恢复并读回；恢复本身失败需明确报错，不能显示“已恢复” |
| 订阅为空或首次使用 | 引导导入，无“已连接”假状态 | 预览确认后加入节点，代理是否开启仍尊重用户选择 |
| 后台服务退出 | 状态未知/服务故障 | 有界重试并展示原因；不能靠重开 UI 产生多个实例 |

原型提供六个演示情景：正常、断网、节点失败、更新失败、空配置、授权取消。它不能证明实际恢复可靠性或任何网络可用性。

## 更新和技术边界

生产前端 Qt/QML，常驻管理层 Rust 优先，代理协议继续复用 Xray/sing-box 上游核心。只在实测热点才引入 Zig/C/汇编，不通过增加语言数量承诺性能提升。

GitHub 自动化先发现稳定版本并形成候选变更，执行兼容与失败恢复测试后发布候选；Omarchy → Arch → 官方上游渠道优先。设备只激活已验证组合，保留上一份可用包/配置。不得自动覆盖包管理器文件，不将私人节点、订阅或凭据送入公共 CI。此轮未新增更新 workflow。

完整订阅格式兼容、自定义规则编辑、核心配置迁移、日志导出及真实 TUN 生命周期均不属于 HTML 原型实现。下一阶段实施计划首先定义已安装版本的能力矩阵和只读状态接口，再实现可恢复的控制操作。

## 验收与后续拆分

本轮设计检查：页面可切换、草稿与生效分离、快捷入口状态一致、失败保留旧状态、横竖屏无水平溢出、主按钮尺寸和页面内错误日志。已执行结果见[原型验证记录](../../validation/2026-10-18-proxy-ui.md)。真实手指、生产 QML、核心与系统集成未验。

正式实现按顺序拆为：①统一状态和单一控制归属，先只读接入；②节点/配置事务与核心兼容；③订阅/规则编辑与四类更新；④系统集成与实机网络验收。各阶段单独计划、验证与恢复，不能因网页演示通过便替换现用代理。

用户审阅重点：总览信息是否一眼清楚、选节点/分流是否顺手、七页划分是否合适。确认书面规格后再形成实施计划。
