# 更新边界

四类组件分别记录：工作台程序、代理核心、分流规则、私人订阅。

- 核心优先 Omarchy、其次 Arch 包渠道。上游 GitHub 发布只作为版本线索，不能绕过发行版兼容检查覆盖 `/opt` 内的核心。
- GitHub 每日工作流读取固定上游的稳定发布元数据，保存可审查的提案 artifact。它不自动合并、不向私人构建机连接、不在平板安装软件。
- 本机“检查稳定版本”只读取元数据。飞行或未知状态暂停，4G或未知出口延后；用户关闭代理后不会为检查而重新打开。
- 发布页声明的 SHA256 是预期摘要。下载后摘要一致也不等于签名认证；界面区分“未下载”“摘要一致”“未认证签名”。当前提案不声称完成安装包签名认证。
- 缓存超过24小时或时间在未来，不作为新鲜证据。未知来源、摘要不符、预发布版本不能进入稳定应用流程。
- 规则后续应用须经候选配置原生校验、事务和恢复；订阅在订阅页先预览目录差异。此版本不提供未经验证的自动热更新按钮。

GitHub 软件检查与本机网络验收分别记录。CI不连接私人节点；真实协议/TUN兼容矩阵在专用远程网络命名空间执行，真实节点只在平板私有候选目录测试。
