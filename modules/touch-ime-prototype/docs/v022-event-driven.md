# v0.2.2 焦点事件驱动

目标是取消空闲时每100ms的同步State查询，保留现有P1手动唤起、Rime九键/全拼、手写、语音与编辑操作。此版本仍使用Fcitx焦点桥；Wayland原生后端另行实现和验收。

## 协议与生命周期

- 桥接状态协议2：State返回初始快照；StateChanged在焦点、敏感能力、屏幕键盘能力变化时发送同格式快照。无关能力变化不发送。
- 后端先订阅当前唯一D-Bus owner，再异步读取State。新通知使旧查询回复失效，owner变化使整个旧会话失效。
- 服务注册早于桥加载时最多重试4次；连接稳定后没有定时查询。P1在未连接时可以主动重试。
- UI代次独立于服务计数。焦点或服务变更会清除组合、语音与手写状态，旧候选和旧请求不能因计数复用而生效。
- Commit/Key仍是按用户操作触发的同步调用，最多等待300ms。其异步化不包含在本次范围内。
- 桥和后端配套更新；不支持协议2的服务会显示等待连接。个人词库与短语配置不变。

## 验证

使用tests/test_backend.py的私有会话总线，测试空闲零查询、九键/全拼提交、手写、模拟语音、编辑操作、密码字段、焦点切换、唯一owner更换、旧owner通知、延迟快照与失效请求。tests/test_bridge.cpp通过真实Fcitx InputContext验证通知内容。完整九项CTest在远程构建机执行，平板验证回传ABI及真实应用。

可选性能对照：在同一机器、同一隔离环境分别执行：

```sh
dbus-run-session -- python tests/benchmark_focus.py /path/to/omt-backend /path/to/rime
```

它使用临时词库，报告3秒空闲State次数、CPU计时、主线程自愿切换及40次合成焦点通知延迟。它不测物理触摸、候选计算、真实应用提交或电池耗电。短时CPU零计时不代表绝对零耗电。

## 部署与恢复

先验证远程回传，再备份旧的后端、桥和插件清单。用同目录临时文件加原子rename替换二进制，不能原地覆盖正在映射的共享库。重启用户Fcitx服务加载新桥，再用新的QML版本目录热加载输入面板。不重启整个桌面壳。

恢复时恢复匹配的旧桥、后端与旧插件清单，重新加载Fcitx和插件；不要删除个人Rime目录，不恢复已废弃的桌面旧键盘。启动解密和锁屏键盘不属于本模块。
