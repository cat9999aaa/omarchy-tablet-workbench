# Omarchy 触屏中文输入法 v0.1

2026-10-16：用户确认自主开发，默认右侧独立面板、键区下置，并明确要求直接实施、后续优化。沿用 Superpowers 的规格、计划、测试与验收，按用户指令不重复设置方案审批门槛。

## 目标与边界

面向本机 Omarchy 4.0.4、Hyprland 0.56.2、Quickshell 0.3.1、Fcitx5 5.1.22。自己的原生 QML 面板通过 Omarchy overlay 插件机制加载。显示拼音/数字组字串、可点选候选字、九宫格、字母/数字/符号与离线语音。只向当前有效输入上下文提交；语音先预览，用户点提交，不自动发送消息。

右侧预留约 440 逻辑像素，键区位于面板下部，候选与预编辑固定在内部。PanelWindow 不取得键盘焦点；关闭时释放预留区域。Fcitx5 输入焦点可观察的应用自动弹出，手动收起直到新的焦点上下文或手动呼出。不能观测的应用提供手动入口，不能伪装为全应用兼容。敏感输入禁止中文学习和语音，仅直接字母/数字/符号。

## 架构

1. 原生 C++ Fcitx5 模块：观察焦点、销毁、敏感能力变化；通过用户会话 D-Bus 提供焦点代次和受代次校验的文字/编辑键提交。只导出焦点元数据，不读取应用正文。引用指针销毁前清除。
2. 独立 C++/Qt 后端：自己的 Rime 会话和用户目录，使用 Arch 提供的 librime 与词典；九键方案用标准数字映射，不依赖手机专有 t9_processor。JSON 行协议与 QML 连接；切换输入对象清空组字。参考上游接口不复制其 UI。
3. QML 面板：Omarchy overlay 生命周期、原生 layer-shell 预留空间、候选与九键统一显示。手动入口和 IPC。v0.1保留旧P1；用户委托自动测试并要求继续收尾后，v0.1.1将P1接新面板并提供旧键盘失败回退，P2/P3及锁屏保持。
4. 语音：用户触发 PipeWire 录音，复用已安装 Voxtype/SenseVoice 离线转写；录音和转写在异步进程中执行，临时目录0700，结束后移除音频。结果留在面板预览；输入对象变化不得误提交。首版承受转写时额外模型内存，后续优化常驻模型共享。

## 验收

- 64426九键序列产生“你好”候选且点选提交，不将数字串写入编辑器。
- 全拼 nihao 产生候选；英文和数字直接输入，退格/回车可用。
- 关闭面板不失去应用焦点且归还空间；手动收起不被状态轮询重新打开。
- 候选、语音结果在焦点变化后作废；失焦/销毁禁止提交。
- 敏感上下文不进入 Rime 或录音。
- 不改 Omarchy 打包内容、不改认证、无 root 后台服务。
- 单元测试、编译、QML加载、合成编辑器真实输入、用户触屏验收分别记录。
